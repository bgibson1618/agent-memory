agent-memory: a cross-agent knowledge base

Concepts captured once are retrievable by any coding agent, in any project, from a fresh session. Local-first: markdown source of truth, three fused indexes, zero egress.

1,346 concepts live · 12/12 features proved · 24 Jul 2026

One-liner from the repo README. Week-1 scope: the memory harness itself, the learning-science knowledge base built on it, and a study course generated from that KB. Everything shown runs on this laptop.

Origin

From capstone harness to personal KB

  • Gauntlet capstone (agent-memory-harness, 4-person team): a model-agnostic memory harness for long-running coding agents — hypothesis: a small model with memory beats a frontier model without, scored on public memory benchmarks
  • My slice there: the storage backends — markdown, sqlite-vector, graph — and the retrieval router across them
  • agent-memory keeps that architecture shape, rebuilt clean-room in a week (no capstone code ported; the OKF markdown format is a public spec)
  • Different question: not “does memory beat parameters?” but “can every agent I run share one knowledge base?”
Capstone: github.com/kenhuangus/agent-memory-harness — benchmark-driven (SWE-Bench-CL as arbiter), explored FalkorDB, rerankers, learned routing. This repo trades all that for a minimal local-first cut. Clean-room posture is DECISION_LOG D2, amended 2026-07-22: OKF is a public standard, so the question dissolved.

Save path and the three indexes

  • mem save / mem extract write one OKF markdown file per concept; every save is a git commit in the KB's own history (zero remotes, for life)
  • Each write feeds three derived indexes — all rebuildable with mem reindex
  • Retrieval: mem search fuses the three rankings with reciprocal-rank fusion; mem get <slug> returns the full body
  • Ollama down → lexical + graph still answer; embeddings queue and drain when it returns

How agents actually use it

  • mem init installs managed instruction blocks into CLAUDE.md / AGENTS.md — fresh sessions search before work and save durable concepts unprompted (observed, not just claimed)
  • Vendor-scoped by policy: Claude and Codex do memory work; Gemini-family agents are excluded, with one scoped exception for public-source extraction that never reads KB bodies
  • Zero egress proved in the test suite: every command runs inside a loopback-only network namespace; the only network peer is local Ollama
  • Every CLI call logs one line; mem stats reports usage by command and day — day one recorded ~300 retrievals from real agent work
Sources: FEATURES F11/F12, DECISION_LOG D1 (vendor scope) and D8 (usage log). The ~300 gets on day one came from question-bank generation pulling live concept bodies — batch pipelines get() by known slug; ambient sessions search() first.

Learning-science extraction

Fixed pipeline per source: chunk → two extractor lenses per chunk → cross-vendor review with arbitration → embedding dedup gate (0.79, calibrated) → strict adjudication against the live KB → near-duplicate fold pass.

Public sources fan out across Claude, Codex, and Gemini lenses; work-tagged sources stay Claude/Codex. A census side-channel rosters every researcher any source cites.

A course generated from the KB

  • 18 modules from an embedding-clustered concept map; 309 anchor concepts, elaborations ride their anchors
  • The pedagogy is the KB applied to itself: retrieval-first sessions, adaptive spacing (+1/+3/+7/+21/+60d), interleaved discrimination, mastery = two delayed independent successes
  • A deterministic planner + a /session skill drive two 45-minute sessions a day; question banks are pre-generated and cue-sweep audited (module 1: 45 items · module 2: 85)
  • ~15±3 weeks at current cadence; session telemetry revises the estimate
Course repo: ~/projects/learning-science/course (SPEC.md, docs/DESIGN.md — 30 KB-cited pedagogy decisions, triple-reviewed). Banks are generated from live KB bodies via mem get, then cue-sweep audited cross-vendor (~20% drop rate both modules). First session ran today. Next slide shows what a session looks like.

Live course

Module 1 — session view

A /session teach segment (anchor 1 of 3, cognitive load theory) — lesson content is generated live from the KB concept bodies, never from static notes.

The session driver picks today's anchors and due reviews deterministically; the agent teaches from mem get bodies. Teach segments cap at 3 anchors per DESIGN.md; checks and review queues follow in the same 45-minute block.
